Статьи — это обычные текстовые файлы в формате **Markdown**: вы ставите несколько простых символов, и они превращаются в оформленный текст. В каждом разделе ниже сначала показано, что написать, а затем — как это выглядит на сайте.

<!--more-->

## Где хранятся статьи {#where}

Каждая статья — это папка внутри `content/posts/`. В ней лежит по одному текстовому файлу на каждый язык, а также фото и файлы статьи:

```text
content/posts/my-article/
├── index.uz.md        ← узбекский (латиница)
├── index.uz-cyrl.md   ← узбекский (кириллица)
├── index.ru.md        ← русский
├── index.en.md        ← английский
└── photo.jpg          ← общий для всех языков
```

Имя папки становится адресом страницы, например `/ru/posts/my-article/`. Используйте только строчные латинские буквы и дефисы.

Чтобы начать новую статью, скопируйте существующую папку или выполните:

```bash
hugo new posts/my-article/index.ru.md
```

## Заголовок файла {#header}

Каждый файл начинается с блока между двумя строками `---`. В нём хранятся настройки статьи, а не её текст:

```yaml
---
title: "Как получить студенческую визу D-2"   # в списке и на странице
date: 2026-10-03T12:00:00+09:00   # дата публикации; список сортируется по ней
draft: true                       # true = скрыта; видна только с `hugo server -D`
categories: ["Руководства", "Визы"]   # одна или несколько категорий
description: "Одно предложение под заголовком в списке статей"
---
```

- Когда статья готова к публикации, поставьте `draft: false`.
- В каждой статье есть оглавление, собранное из её заголовков. Чтобы скрыть его, добавьте в заголовок файла `ShowToc: false`; `TocOpen: true` показывает его сразу раскрытым.
- После публикации статьи в Telegram-канале добавьте `telegram: "https://t.me/kvp_partners/123"` (ссылку на пост), чтобы под статьёй появились комментарии к этому посту.
- Пишите каждую категорию одинаково во всех статьях одного языка: «Виза» и «Визы» станут двумя разными кнопками.
- Фото в начале статьи (`cover`) описано в статье [Как добавлять фото, видео и файлы](/posts/guide-media/).

## Заголовки {#headings}

Название статьи — самый крупный заголовок, поэтому заголовки внутри текста начинаются с двух `#`:

```markdown
## Раздел
### Подраздел
#### Заголовок поменьше
```

На этой странице они уже используются: «Заголовки» выше — это `##`, а «Жирный, курсив, зачёркнутый» ниже — `###`. Из заголовков также собирается содержание в начале страницы.

## Абзацы и переносы строк {#paragraphs}

Между абзацами оставляйте пустую строку. Одиночный перенос строки игнорируется; чтобы начать новую строку внутри абзаца, поставьте в конце строки обратную косую черту `\`.

```markdown
Первый абзац.

Второй абзац,\
с принудительным переносом строки.
```

Первый абзац.

Второй абзац,\
с принудительным переносом строки.

## Оформление текста {#text-styles}

### Жирный, курсив, зачёркнутый

```markdown
**жирный**, *курсив*, ***жирный курсив***, ~~зачёркнутый~~
```

**жирный**, *курсив*, ***жирный курсив***, ~~зачёркнутый~~

### Выделение, подчёркивание, нижний и верхний индекс

```markdown
==выделенный==, ++подчёркнутый++, H~2~O, 25 м^2^
```

==выделенный==, ++подчёркнутый++, H~2~O, 25 м^2^

### Код в строке

Для точных значений, имён файлов или команд:

```markdown
В анкете тип визы пишется как `D-2`.
```

В анкете тип визы пишется как `D-2`.

### Автоматическая типографика

Прямые кавычки, двойной дефис и три точки заменяются автоматически:

```markdown
"Кавычки" -- короткое тире --- длинное тире...
```

"Кавычки" -- короткое тире --- длинное тире...

Кавычки-«ёлочки» и любые другие символы вставляйте напрямую: «», №, ₩, €, ©, 🇰🇷 🎓 ✈️.

## Ссылки {#links}

```markdown
- [Сайт](https://www.hikorea.go.kr)
- <https://www.visa.go.kr>
- [Адрес электронной почты](mailto:info@example.com)
- [Другая статья этого блога](/posts/guide-media/)
- [Раздел этой страницы](#tables)
```

- [Сайт](https://www.hikorea.go.kr)
- <https://www.visa.go.kr>
- [Адрес электронной почты](mailto:info@example.com)
- [Другая статья этого блога](/posts/guide-media/)
- [Раздел этой страницы](#tables)

Ссылка на другую статью (`/posts/…`) сама открывает её на текущем языке читателя. Обычный адрес вроде https://www.visa.go.kr тоже сам становится ссылкой.

Ссылка на раздел использует имя в фигурных скобках после его заголовка. Например, раздел с таблицами на этой странице записан как `## Таблицы {#tables}`. Без скобок имя берётся из текста заголовка, а он на каждом языке свой.

## Списки {#lists}

### Маркированный список

```markdown
- Паспорт
- Фото 3,5 × 4,5 см
  - на белом фоне (отступ — два пробела)
  - сделанное не раньше чем 6 месяцев назад
- Анкета
```

  - на белом фоне (отступ — два пробела)

### Нумерованный список

```markdown
1. Собрать документы
2. Записаться на приём
   1. Выбрать дату (отступ — три пробела)
   2. Оплатить сбор
3. Пройти собеседование
```

1. Собрать документы

```markdown

| Фото        |     2 |   ✓    |
```

| Документ    | Копий | Готово |

## Блоки кода {#code}

Поставьте три обратных апострофа на строках до и после кода. Название языка после первых апострофов добавляет подсветку:

````markdown
```python
def days_left(stay, used):
    return stay - used
```
````

```python
def days_left(stay, used):
    return stay - used
```

Номера строк и выделенные строки:

````markdown
```python {linenos=true, hl_lines=[2]}

    return stay - used
```
````

## Раскрывающийся блок {#collapsible}

Удобно для вопросов и ответов: содержимое скрыто, пока читатель не нажмёт.

```markdown
{{</* details summary="Можно ли здесь оформлять текст?" */>}}
Да: **жирный**, *курсив*, [ссылки](#links) и списки работают внутри.
{{</* /details */>}}
```

## Как показать символ как есть {#escaping}

Поставьте обратную косую черту перед символом, чтобы он не превращался в оформление:

```markdown
\*не курсив\*, 5 \* 3
```

\*не курсив\*, 5 \* 3

## Описание в списке статей {#preview}

Каждая карточка в списке статей показывает под заголовком описание статьи: `description: "…"` в заголовке файла. На странице самой статьи его нет, поэтому пишите его так, чтобы читателю захотелось открыть статью. Если описания нет, карточка показывает начало текста: текст до строки `<!--more-->` (в этой статье она стоит после первого абзаца), а без этой строки — примерно первые 70 слов.
